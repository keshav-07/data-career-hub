# Deployment: Cloudflare Workers Static Assets

The site is a static `dist/` folder. No Worker script, adapter, database or secret is needed.

## One-time setup

1. **Production domain: `https://datadank.com`.** It is the default `site` in `astro.config.mjs`, so canonicals,
   Open Graph URLs, JSON-LD, the sitemap and `robots.txt` (generated by `src/pages/robots.txt.ts`) all use it
   without any build variable. Set `SITE_URL` only for a deliberate non-production build.
   `npm run check:dist` fails if any canonical, `og:url`, JSON-LD, sitemap or robots.txt names another origin,
   a placeholder (`datadank.example`) or a preview host (`pages.dev`, `workers.dev`).
2. **Cloudflare account.** `npx wrangler login` (or create an API token with *Workers Scripts: Edit*) on the machine or CI that deploys.
3. **Update `compatibility_date`** in `wrangler.jsonc` to the deployment date.

## Build and deploy

```bash
npm ci
npm run validate                                 # check, lint, contrast, inventory, build (+ Pagefind), dist checks
npx wrangler deploy --dry-run                     # confirms the assets config
npx wrangler deploy
```

`wrangler.jsonc` serves `./dist` with `not_found_handling: "404-page"` (real 404 status using `dist/404.html`)
and `html_handling: "force-trailing-slash"` (matches the canonical URL policy).
`public/_headers` sets security headers and `public/_redirects` holds the redirect map.

## Custom domain and HTTPS

In the Cloudflare dashboard: Workers & Pages → `datadank` → Settings → Domains & Routes → add the custom
domain. Cloudflare provisions the certificate. Verify `https://` loads and `http://` redirects.

## Post-deploy verification (task P8-05 to P8-09)

```bash
curl -sI https://datadank.com/does-not-exist/ | head -1     # expect 404
curl -sI https://datadank.com/sql | grep -i location         # expect redirect to /sql/
curl -s  https://datadank.com/robots.txt
curl -s  https://datadank.com/sitemap-index.xml
curl -sI https://datadank.com/ | grep -iE "content-security|x-content-type|referrer"
```

## Preview hosts

`datadank.pages.dev` and preview deployments serve the same build. `public/_headers` sends
`X-Robots-Tag: noindex` on `*.pages.dev`, and their canonicals already point at `https://datadank.com/...`,
so they do not compete with the production domain in search. Pick one host for `www`
(`www.datadank.com` → `datadank.com` with a 301 Redirect Rule in Cloudflare) so only one origin is reachable.

## Analytics (optional)

Enable Cloudflare Web Analytics for the site, then build with `PUBLIC_CF_ANALYTICS_TOKEN=<token>`. Also:

- add `https://static.cloudflareinsights.com` to `script-src` and `https://cloudflareinsights.com` to `connect-src` in `public/_headers`;
- the privacy page updates automatically from the same variable.

## Search Console

Verify the domain property in Google Search Console (DNS TXT record), then submit `https://datadank.com/sitemap-index.xml`.

## Continuous deployment (optional)

Connect the GitHub repository in Cloudflare (Workers Builds) with build command `npm run build`, deploy command
`npx wrangler deploy` (no `SITE_URL` needed for production).
